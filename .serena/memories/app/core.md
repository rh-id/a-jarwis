# :app Module Core

Entry module, namespace `m.co.rh.id.a_jarwis`. See `core` for module graph.

## App skeleton
- `MainActivity`: only activity, singleTop, all configChanges declared (state via a-navigator)
- `MainApplication`: creates Provider from `AppProviderModule`, global crash handler (log via ILogger → dispose provider → chain default handler), WorkManager `Configuration.Provider` using provider executors
- `AppProviderModule` = composition root; registers Base/Rx/Settings/MLEngine modules (no Command modules anymore), `IStatefulViewProvider` pool, NavigatorProvider LAST (order matters)

## Navigation
- `NavigatorProvider`: builds `Navigator` for MainActivity; navMap Routes→StatefulViewFactory; NavExtDialogConfig merged; loading view = page_splash layout
- To add a page: constant in `:base` `Routes` + factory here + page class in `ui/page`

## Pages (`ui/page`)
- `SplashPage` (start route) → `HomePage` (route `/`, drawer menu: settings, donations; 7 feature buttons: Blur Face, Apply Neural Style Transfer, Censor QR Codes, Scan QR Codes, Portrait Mode, Magic Eraser, AI Image Detector)
- `HomeWorkflow` (helper held by HomePage): WRITE_EXTERNAL_STORAGE request (≤ S_V2), blur flow checks FACE_DETECT, portrait flow checks PERSON_SEG model availability first (missing → pushes `ModelDownloadDialog` and continues on POSITIVE), then ACTION_GET_CONTENT multi-pick → pushes an editor with `UriList`; magic eraser flow checks BOTH EFFICIENT_SAM + LAMA (missing → ModelDownloadDialog), single-image pick via the `pickImage(requestCode, allowMultiple)` overload (omits EXTRA_ALLOW_MULTIPLE when false, REQUEST_CODE_IMAGE_MAGIC_ERASER = 8) and takes only the first uri; QR censor flow = storage permission + pick, NO model check (in-box OpenCV detector); AI detect flow gates AI_IMAGE_DETECT (missing → ModelDownloadDialog) then a single-image pick (REQUEST_CODE_IMAGE_AI_DETECT = 9); QR scan flow = CAMERA permission (`requestCameraPermission`, all SDK levels) then pushes QrScannerPage directly (no route args, no model)
- `editor/FaceEditorPage` (route `/editor/faceEditor`): interactive face-blur editor — FaceEngine.detectFace on a downscaled preview, tap a face to toggle its blur, per-image `BlurConfig` (ellipse/square + strength 1..5), full-res composite on save/share; dispose submits `MLEngineInstance.releaseFaceModels()` to the executor so the cached SFace/YuNet nets stay resident only during face sessions (MagicEraserEditorPage's SAM/LaMa release pattern)
- `editor/StyleEditorPage` (route `/editor/styleEditor`): interactive NST editor — per-image style tiles (0=original, `STEngine.THEME_*` 1..5), live preview via `STEngine.apply`, apply-to-all (disabled while original selected), on-demand model download per style (checks `ModelCatalog.isAvailable`, pushes ModelDownloadDialog, re-renders on POSITIVE)
- `editor/PortraitEditorPage` (route `/editor/portraitEditor`): background blur / remove-background editor — per-image mode (blur/remove) + blur strength on downscaled preview; masks come from `PersonSegEngine.getMask` (`PersonSegMask` handle, engine-cached so toggles are instant, handle non-Serializable → rebuilt via getMask on restore, `releaseAllMasks` on dispose); Blur mode exports JPEG, Remove mode exports PNG with preserved alpha (`image/png` share mime); no-person state persisted per image
- `editor/MagicEraserEditorPage` (route `/editor/magicEraserEditor`): object removal editor, SINGLE image — AUTOMATIC detect flow, no Detect button (it was removed): user paints strokes with `ui/component/BrushOverlayView` (transient view, vector Paths only, holds a reference to the state stroke list, normalized 0..1 points mapped through a copy of the image view matrix; page resyncs the matrix on image view layout changes) → a DEBOUNCED auto-detect fires 1 second after each stroke commit/undo/erase (`scheduleAutoDetect`, Rx key `autoDetect`, a newer commit cancels the pending older timer so only the newest marking reaches the seconds-long SAM inference; the detect itself = `detectObject`, unique Rx key `detectObject`, busy-guard progress) → `computeObjectMask` + `toOverlayBitmap` (`MagicEraserMask` handle, no org.opencv in :app) shows the detected mask as a 50%-opacity white tint with the committed strokes hidden (they reappear on any stroke change); the detected mask is KEPT keyed by stroke-list identity (`sameStrokes`, committed strokes never mutate) and any stroke change (commit/undo/reset, or the erase consuming it) releases it (tint cleared, strokes visible again); **Erase** (`removing_progress`) reuses the detected mask when strokes are unchanged since the Detect (halves the erase latency) else recomputes → `hasMask` gate ("no object detected" note) → SAM processor RELEASED before the erase launches and LaMa released after EVERY erase attempt (success+failure; a failed erase keeps SAM so the self-heal re-detect doesn't reload it) → the erase input is the decoded source handed to `MagicEraserEngine.eraseObject` (engine-owned pipeline: `applyBatches` history REPLAY first — so erase #2 operates on the image with erase #1 applied, matching save/share/restore exactly; without this the first erased object reappeared on screen — then mask compute-or-reuse + `eraseRegion`; the page passes `() -> mIsDisposed` as the engine's CancelledCheck and transfers mask ownership to the engine) → result becomes the new preview base and the strokes commit as a `StrokeBatch` (`ml_engine.model`, moved out of the page pre-release) into `mApplyHistory` (cap 10, full → erase rejected with a dialog; `mCurrentStrokes` cap 50, oldest dropped); detect uses a main-thread COPY of the preview base (single-owner AtomicReference handoff; the task recycles it; source re-decode only as fallback), so post-erase detects segment the current image; undo/reset work on the current strokes only, committed batches are final; process-death restore replays all batches at preview res behind a progress dialog; save/share replay ALL batches at full res (decodeFullBitmap), JPEG export via `MediaHelper.insertImage` / `createImageTempFile` + `UiUtils.shareFile` (`image/jpeg`); **net-release lifecycle** (the ~1GB native retention fix — cv::dnn keeps ~591MB SAM / hundreds-of-MB LaMa workspaces inside the cached nets): page dispose releases SAM+LaMa on the background executor (never the main thread — release blocks on the processor monitor), and every pipeline carries a dispose contract: `delivered` flag + result parked in an AtomicReference + `disposed` flag with CAS self-release in the callable, so a dispose mid-pipeline releases the produced result exactly once; in-flight tasks abort on `mIsDisposed` (IllegalStateException inside the try/finally chains) instead of lazily re-parsing released nets into the cache; the pre-erase source-copy registration checks `mIsDisposed` under the session-files monitor (loser deletes the file); source copied to a private temp file (prefix `magic_eraser_source_`) before the FIRST erase, state uri replaced with the file uri. ACCEPTED 32-bit limitations (api24 x86 AVD, measured 2026-10-29): inference failures under memory pressure are GRACEFUL by design — a caught CvException/Java OOM shows the `error_insufficient_memory` toast, keeps the strokes, self-heals (re-detect restores the tint), never crashes (live-verified: an erase failing on an ART bitmap-mmap OOM from system RAM exhaustion behaved exactly so); do NOT attempt co-residency optimizations — resident SAM + LaMa load = instant native SIGABRT (uncatchable std::bad_alloc in libc++_shared, fresh process, process death), and a long-running 32-bit session fragments the VA until even SAM's ~192MB contiguous reload forward fails; 64-bit devices are unaffected apart from the SAM re-parse per erase. Also observed once on this AVD: process-death restore came back with an EMPTY preview (blank image area, empty strokes) — known restore-path gap, pre-existing
- `editor/QrCensorEditorPage` (route `/editor/qrCensorEditor`): interactive QR-censor editor, multi-image — each picked image shows detected QR codes outlined on a downscaled preview, tapping a QR toggles its censor blur; detection = `QREngine.detectQrCodes` (DETECT-ONLY so undecodable codes still report and can be censored) at a downscaled detect resolution with rects rescaled to the preview; censoring reuses the FaceEngine blur kernels (`blurFaceCrop` per preview crop, `blurFacesAt` for the full-res composite) with the same per-image `BlurConfig` (ellipse/square toggle + strength slider, initial state SHAPE_SQUARE + STRENGTH_MAX); NO model gate (OpenCV `QRCodeDetector` is in-box, no download) and no model release on dispose (the blur path uses no native model); per-image preview cache invalidated on config change; sources copied to temp files (prefix `qr_editor_source_`, 1h age purge, deleted on dispose — its own `copySourceToTempFile` keeps a plausible original extension, falls back to the original uri on copy failure); save/share composites at full resolution like the face editor (`MediaHelper.insertImage` / `ImageHelper.createImageTempFile` + `UiUtils.shareFile`)
- `QrScannerPage` (route `/qrScanner`): live camera QR scanner — HomeWorkflow requests CAMERA permission BEFORE the push; CameraX `Preview` + `ImageAnalysis` with STRATEGY_KEEP_ONLY_LATEST, frames decoded per-frame via `QrFrameDecoder` (Y-plane → grayscale Mat honoring rowStride, rotated upright) on a dedicated single-thread analyzer executor (the decoder is stateful, NOT thread-safe); decode runs behind a single-in-flight guard, results into a list with per-line copy, "copy all" (enabled ≥ 2 results), URL link spans (Linkify + `LinkMovementMethod` — the span tap dispatches the ACTION_VIEW intent); in-page "scan from image" picker (multi-pick) runs the same decode on picked bitmaps; no OpenCV type crosses into :app (`QrFrameDecoder` is the Mat-free camera path); dispose releases the decoder on the analyzer executor then shuts it down
- `AiDetectPage` (route `/aiDetect`): AI image detector, SINGLE image — model gate lives in HomeWorkflow (AI_IMAGE_DETECT missing → `ModelDownloadDialog`); one classify → `pFake` 0..1 (`AiDetectEngine.classify` on a sampled decode within the preview budget, one Rx pipeline); confidence bands: LIKELY_AI ≥ 0.75, LIKELY_REAL ≤ 0.35, else "unclear" (`BAND_THRESHOLD_*` constants, calibrated by the issue-#12 on-device run); shows the AI percentage + a standing disclaimer (probabilistic estimate, never evidence); "Check another image" (`button_pick_another`) re-picks in place without leaving the page and doubles as the retry path; the cached processor is KEPT for the page session and released on dispose via `mExecutorService.submit(engine::release)` (release blocks on the processor monitor — never the main thread), exactly-once bitmap ownership between result delivery and dispose cleanup
- `common/`: only `ModelDownloadDialog` (pushed dialog for on-demand model download with progress; pops `SelectedChoice.POSITIVE` when done) — used by the editors + HomeWorkflow
- params in `ui/page/nav/param`: `UriList`, `SelectedChoice` (Serializable; uris stored as strings)

## Editor page architecture (shared by the editors)
- `StatefulView` + `RequireComponent<Provider>` + `NavOnBackPressed`; deps pulled in `provideComponent()` via `IStatefulViewProvider`
- Single non-transient `final SerialBehaviorSubject<EditorState>` holding ONLY-Serializable state (String uris, ints, Booleans); views/bitmaps stay transient, never in the navigator snapshot
- Background work via `mRxDisposer.add("<unique key>", ...)` + `Schedulers.from(mExecutorService)`, observed on main thread with stale-guard re-check
- Copy-on-pick: content uris → temp files (prefixes `editor_source_` / `st_editor_source_` / `qr_editor_source_` / `magic_eraser_source_` — the magic eraser copies only before its first erase, 1h age purge on createView, deleted on dispose); the magic-eraser and portrait pages use the shared `FileHelper.copySourceToTempFile(String, Uri)` (callers must pass a name WITH a dot extension — the helper cuts at the last dot); the QR-censor page has its own copy helper on `FileHelper.createTempFile`
- Modal progress dialog = busy-guard — shared `ui/component/EditorProgressDialog` (`isWorking/show/update/hide/dispose`; busy-guard reads `mDialog != null && isShowing()`), used by MagicEraser + Portrait editors; save via `MediaHelper.insertImage` (CompressFormat overload adds PNG for alpha cutouts), share via `ImageHelper.createImageTempFile(String,Bitmap[,CompressFormat])` + `UiUtils.shareFile`

No tests in :app.
