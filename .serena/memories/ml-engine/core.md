# :ml-engine Module Core

All ML logic. Java 1.8 source/target (differs from other modules — intentional). Models are NOT bundled in the APK — they are DOWNLOADED on demand into `filesDir/ml-engine/engine/**`.

## Workers (`workmanager`)
- `ModelDownloadWorker` — the ONLY WorkManager worker left: unique work per model (`ExistingWorkPolicy.KEEP`), network-connected constraint, exponential backoff; input `Params.MODEL_TYPE` (model id string) + failure output `Params.ERROR_MESSAGE`; get deps via `BaseApplication.of(ctx).getProvider()`
- `ModelChangeNotifier` (`provider/notifier/`): hot progress/succeeded/failed flows — consumers must be subscribed at emit time

## Registration
`MLEngineProviderModule`: MLEngineInstance async (`registerAsync` starts construction on a background thread at provider START — not deferred to first get; get() blocks on the future); FaceEngine/QREngine/STEngine/PersonSegEngine/DepthEngine/MagicEraserEngine/AiDetectEngine/ModelDownloader/ModelChangeNotifier lazy (`registerLazy` = supplier runs on first get(), synchronized, memoized).

## Adding an ML feature (canonical recipe)
1. model file: add a `MLEngineInstance.ModelType` entry (id/displayName/displaySize/downloadUrl → downloaded via ModelDownloadWorker) OR bundle + register path constants in MLEngineInstance
2. engine method in FaceEngine/STEngine or a new engine; gate on the engine facade's availability method (generic per-ModelType checks = the PACKAGE-PRIVATE `MLEngineInstance.isModelAvailable(ModelType)`, same package only) and expose an opaque id accessor (`xxxModelId()` / STEngine `modelIdForTheme`) — `ModelDownloadDialog`/`ModelDownloadWorker`/`ModelChangeNotifier` key everything on the String id; push `ModelDownloadDialog` (`:app`) for on-demand download
3. register in MLEngineProviderModule; androidTest uses `MLEngineTestProviderModule` (+ `ModelTestHelper.installModels(provider, ModelType...)` — varargs so a test only downloads the models it needs; the no-arg overload installs the whole catalog — blocking download, needs network; the helper checks/re-verifies through `MLEngineInstance.isModelAvailable`)

Tests (androidTest only, need emulator + network): ONE test class per engine component — `FaceEngineTest`, `STEngineTest`, `PersonSegEngineTest`, `DepthProcessorTest`+`DepthEngineTest` (depth: dims/range/flat-guard on landscape.jpg (the permanent landscape fixture, renamed from the throwaway spike asset), deterministic closeness-polarity far<near-0.15; far/near blur DISCRIMINATION is SYNTHETIC-only (fixed-seed 16px-block noise + linear closeness gradient fed straight into the package-private Mat lensBlurBackground overload, plain pixel-variance loss fractions, margin +0.25); `lensBlur_publicKeyDrivenFacade_opaqueResult` covers the public prepareDepth→key-driven lensBlurBackground facade end-to-end — real-photo band metrics are dead ends: the absolute Laplacian loss is content-confounded across bands (grainy road vs smooth sky, run 1) AND the relative fractions saturate (run 3: even kernel-3 destroys ~98% of Laplacian variance, 0.978 vs 0.983; per-pixel white noise saturates plain variance too — kernel-3 σ1.5 keeps only ~11%), so the real-photo test only asserts farIncrease>0; scale agreement = per-band fraction parity <0.3 between scale 1.0 and 0.5, whole-image blend result opaque, processor release contract (the lensBlur_hybridKeepsPersonSharp test + the PERSON_SEG install + mPersonSegEngine field were REMOVED with the hybrid path); BOTH classes @AfterClass release the engine-cached processor + gc/runFinalization prelude BEFORE provider.dispose — without it the ~550MB depth workspace kills the later Swin2SR suite via lowmemorykiller in the shared instrumentation process), `QREngineTest` (15 tests, includes the qrCensor_* ZXing-oracle effectiveness tests, installs no models), `MagicEraserTest` (12 tests merged from the former EngineTest/OverlayTest/ProcessorReleaseTest/SpikeTest; NAME_ASCENDING is load-bearing: the SAM spike diagnostic runs FIRST on a clean no-net baseline, the LaMa-only spike runs after the erase tests' finally releases, the release-contract tests run LAST leaving empty caches for @AfterClass), `AiImageDetectProcessorTest` (release-contract test of the AI-image-detector processor; installs the AI model) (work-testing dep).
