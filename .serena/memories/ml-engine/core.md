# :ml-engine Module Core

All ML logic. Java 1.8 source/target (differs from other modules — intentional). Models are NOT bundled in the APK — they are DOWNLOADED on demand into `filesDir/ml-engine/engine/**`.

## Components
- `MLEngineInstance` (`registerAsync` — heavy): `OpenCVLoader.initLocal()` (NOT initDebug); path constants under `filesDir/ml-engine/engine/**` (face/detect, face/recognizer, neural-style-transfer, person-segmentation, object-segmentation, inpainting, ai-image-detect — file `community_forensics_deepfakedet_vit_fp32_2026july.onnx`); `getSTProcessor(theme)` caches one STProcessor per theme (`ConcurrentHashMap.computeIfAbsent`, ~32MB native for all 5, app lifetime); `getPersonSegProcessor()`, `getEfficientSamProcessor()`/`getLamaProcessor()`, `getAiImageDetectProcessor()` same cache pattern per ModelType (EfficientSam ~46MB + LaMa ~93MB on-disk; BOTH nets + their cv::dnn retained activation workspaces total ~1GB+ native after use; AI detector ~87MB on-disk, ~278MB native retained after an inference) plus `releaseEfficientSamProcessor()`/`releaseLamaProcessor()`/`releaseAiImageDetectProcessor()` (map-remove + processor `release()` + `System.gc()`/`runFinalization()` nudge); `isMagicEraserAvailable()` = BOTH magic-eraser models present, `isAiImageDetectAvailable()` gates the AI-detector flow; model getters throw when the model file is missing
- `model/ModelType` enum (11 entries): FACE_DETECT, FACE_RECOGNIZER, NST_MOSAIC/CANDY/RAIN_PRINCESS/UDNIE/POINTILISM, PERSON_SEG, EFFICIENT_SAM (FINAL VERDICT: fp32 `ti_2025april.onnx` ships — both variants verified on device through OpenCV 5 DNN, int8 is functionally correct (the original all-zero observation was the n-dim bulk blob access bug, see below), but fp32 is ~2.4x faster AND more accurate on the verification device (x86_64 emulator: 6.9 s vs 16.4 s per inference, IOU 0.99 vs 0.87); int8's only advantage is the one-time download (20 vs 46 MB); int8 URL recorded in the ModelType javadoc for re-evaluation on real ARM hardware), LAMA, AI_IMAGE_DETECT (~87MB, CommunityForensics DeepfakeDet-ViT binary deepfake classifier, ViT-S/16, HuggingFace `buildborderless/CommunityForensics-DeepfakeDet-ViT` — the CORRECTED 2026-07-22 export regeneration; the stale artifacts (deprecated ...-ONNX repos, the repo's onnx_legacy/ folder) hold WRONG weights and must never be used or re-exported; quantized variants are a double NO-GO: OpenCV DNN cannot load them AND the model card documents 10-70pp OOD divergence for int8/q4; round-2 spike GO 2026-10-31: 5/5 modern AI samples detected (pFake 0.986-1.000), 0/9 false positives, 605ms mean latency; round 1 (jacoballessio distilled ViT) NO-GO, 0/8 detected) — id/displayName/displaySize/downloadUrl (HuggingFace)
- `model/ModelCatalog` (static): `isAvailable` (also runs legacy `nst_*_9.onnx` filename migration), `getModelFile`, `fromTheme`
- `model/BlurConfig`: Serializable blur shape (ellipse/square) + strength 1..5, normalized after deserialization
- `model/EditorStroke`: Serializable brush stroke over the object to erase — normalized 0..1 interleaved x,y points + brush size 1..5 (normalized after deserialization), resolution-independent (rasterized at any target resolution), `getBoundingBox()` union box
- `model/StrokeBatch`: Serializable committed-erase step (ArrayList<EditorStroke>, normalized) — lives in ml_engine.model so page snapshots reference a stable class (moved OUT of MagicEraserEditorPage before first release; descriptor change intentional). `model/CancelledCheck`: custom @FunctionalInterface `{boolean isCancelled();}` — NOT java.util.function (API 24+, minSdk is 21)
- `ModelDownloader`: pure java.net HTTP + SHA-256; HEAD meta fetch runs with `setInstanceFollowRedirects(false)` and reads the HF LFS file sha256 from `X-Linked-ETag` (fallback `ETag`; a non-sha256 ETag = length-only validation — the FINAL Xet ETag is NOT the file sha256, only the initial huggingface.co redirect response carries the real digest/size); GET resumes via the Range header on the FIRST attempt ONLY (the retry after a checksum mismatch is always a clean download); sha256 read through a `DigestInputStream` while streaming; progress events every 64 KiB (`PROGRESS_STEP_BYTES = 65_536`); checksum mismatch → ONE clean retry → `ModelChecksumException` (permanent, failure event fires before the rethrow); success → `FileHelper.atomicMove` into place; digests come from the HF repo headers, NOT a hardcoded table; ALL download events broadcast via `ModelChangeNotifier`
- `FaceEngine`: `detectFace`, `searchFace` (1 face vs N); legacy `blurFace`/`isFaceSimilar` (SFace cosine ≥ 0.363) retained for future reference-image flows. NOTE: `getFaceDetectModel()`/`getFaceRecognizerModel()` in MLEngineInstance construct a NEW native FaceDetectorYN/FaceRecognizerSF per call (uncached, unreleased; `searchFace` builds one SFace per candidate face) — the only model family NOT following the cached-processor pattern, flagged as a pre-existing perf wart to potentially fix in a follow-up. For the editor: `blurFacesAt(Bitmap, List<Rect>, BlurConfig)` (full-res save path) + `blurFaceCrop(Bitmap, scale, BlurConfig)` (preview path) — kernel size scales with face min dimension (strength factors 0.35..1.00, clamped [3,201], forced odd, sigma = kernel*0.5), feathered ellipse/rounded-square masks via BlurMaskFilter + PorterDuff DST_IN
- `QREngine` + `QrFrameDecoder`: OpenCV `objdetect.QRCodeDetector`, NO model file (in-box). `QREngine.detectQrCodes(Bitmap)` → List<Rect> is DETECT-only (`detectMulti` — undecodable codes still report, needed for censoring); `decodeQrCodes(Bitmap)` and the package-private `decodeQrCodes(Mat)` (CV_8UC1 grayscale e.g. camera Y plane, or CV_8UC3; any other type → empty list) use `detectAndDecodeMulti` and skip null/empty texts; a FRESH `QRCodeDetector` per call (the detector holds no model state → native state strictly call-local, thread-safe without locking); detector points Mats read sequentially (`readPoints`) so both OpenCV output shapes work (single row of N points OR 4 corner points per code — every 4 consecutive points = one code), quads → clamped bounding rects (degenerate → null); all Mats released in finally. Nested `QREngine.QrDecodeResult` (Rect + decoded text). `QrFrameDecoder` = the camera-frame adapter so :app never imports org.opencv: converts a camera Y plane byte[] into a grayscale Mat HONORING rowStride (frequently wider than width — reading width bytes/row would skew the image), rotates upright per rotationDegrees (0/90/180/270, reusable preallocated rotation Mat grown on size change), decodes through the QREngine Mat overload; STATEFUL and NOT thread-safe — decode calls must be serialized on the camera analyzer executor; `release()` frees the rotation Mat (a decode after release lazily reallocates); constructor eagerly calls `OpenCVLoader.initLocal()` (prevents the cold-start UnsatisfiedLinkError race while a provider-started init is in flight); invalid input (null/empty plane, rowStride < width) → empty result
- `AiDetectEngine` + `AiImageDetectProcessor` (facade so :app never imports org.opencv): AI-generated-image detection with the CommunityForensics DeepfakeDet-ViT model. `classify(Bitmap)` → pFake 0..1 (sigmoid of the SINGLE output logit, num_labels=1); processor input 384x384: aspect-preserving shortest-edge resize to 440 (bicubic) → center crop → manual CLIP normalization ((x/255 - mean)/std per channel — blobFromImage only supports a SCALAR mean); the threshold policy is deliberately NOT in the processor (the page-side band constants pick the operating point); the constructor SILENTLY falls back to the classic OpenCV DNN engine when the default engine cannot load the graph (readNetFromONNX returns empty instead of throwing on an unparseable graph — silent-failure form); fp32 only (see the ModelType NO-GOs). Lifecycle: the cached processor is created lazily on first classify and KEPT for the page session (per-classify re-parse of ~87MB would wreck UX; ~278MB native retained is real but far below SAM/LaMa levels → NO eager per-step release, unlike the magic eraser); the page releases on dispose via `AiDetectEngine.release()` → `MLEngineInstance.releaseAiImageDetectProcessor()` (FaceEditorPage releaseFaceModels precedent); no-concurrent-calls contract (same rule as ST/PersonSeg); after `release()` the instance is dead, the cache recreates fresh on demand
- `STEngine` + `STProcessor`: NST via OpenCV DNN. Synchronous `apply(Bitmap, theme)` + per-theme applyMosaic/applyCandy/applyRainPrincess/applyUdnie/applyPointilism (used by STEngineTest); `enqueueST` DELETED. `STProcessor.process()` must NEVER run concurrently on one instance — callers serialize via page busy-guards; inference always at 540px longest edge, upscaled back
- `PersonSegProcessor`+`PersonSegEngine`+`PersonSegMask` (handle so :app never imports org.opencv): PP-HumanSeg portrait segmentation via DNN CPU, 192x192 input, blob (x-127.5)/127.5; mask = the person probability channel of the softmax output read directly (the two output channels already sum to 1.0 per pixel: an extra sigmoid would compress the whole mask into the 0.27..0.73 gray ghost range - found by the api24 x86 AVD connected run + region probe), feathered at model resolution, INTER_LINEAR upsample; `computeMask` = caller-owned full-res mask, `getMask(key,..)` = engine-cached (mode/strength toggles re-composite without re-inference), `releaseAllMasks` on editor dispose, `hasPerson` gate = mask sum ≥ 0.2% area; process() never concurrently on one instance (same rule as ST)
- `EfficientSamProcessor`+`LamaProcessor`+`MagicEraserEngine`+`MagicEraserMask` (handle so :app never imports org.opencv): magic eraser = EfficientSAM promptable segmentation then LaMa inpainting, both via DNN CPU. **LOAD-BEARING OpenCV 5 Java bindings constraint: bulk `get/put(0,0,buffer)` on n-dimensional Mats (dims > 2) silently reads/writes ZEROS — every blob access MUST go through a reshaped 2-D view first (`mat.reshape(1, rows)` shares the continuous memory without a copy); found by the spike (all-zero logits read from a real inference, all-zero image-blob stats), the 2-D paths are the proven ones (imagesFromBlob/split/row reads)**. Also: `Core.findNonZero` keeps the C++ `(src, idx)` order (an earlier dst-first assumption from an unverified javap inference passed the empty dst as src and tripped the `src.dims == 2` assertion — javap carries no parameter names, verify orders against the C++ headers; verified src-first: findNonZero/copyTo/compare/connectedComponents, dst-last: merge); EfficientSAM (input at MODEL_INPUT_SIZE=1024 aspect-distorting, /255, RGB no swap): 3 named inputs batched_images / batched_point_coords (1,1,6,2 float, coords in model-input space = normalized nx*SAM_MODEL_INPUT_SIZE, NO image-dim division — double-scaling made a degenerate corner box that segmented everything) / batched_point_labels (1=fg point, 2=box TL, 3=box BR, -1 padding; pad unused with coords 0,0); outputs output_masks (1,1,K,1024,1024 logits, mask = logit ≥ 0 — the export's OUTPUT spatial dims are FIXED 1024x1024 regardless of input size) + iou_predictions (1,1,K) — pick max-IOU candidate (layout-adaptive: the plane side is derived from the OUTPUT BLOB — trailing square plane with side = power of two in [64,4096] — then cropped to the top-left min(plane, MODEL_INPUT_SIZE) content region; leading product = K; empty candidate falls back to next-highest IOU, all-empty → all-zero mask rejected by hasMask). **512-reduction EXPERIMENT (2026-10-29, api24 x86 32-bit AVD) — FINAL VERDICT: REVERTED to 1024, measured findings kept for the record: (1) setInput/forward ACCEPT 512, ~3.3-4.1s per forward vs 6.9s @1024 x86_64 (~2x faster); (2) output dims are FIXED (1,1,3,1024,1024) and the plane CONTENT is tied to the INPUT pixel grid — plane pixel (i,j) = segmentation of input pixel (i,j): a square at input coords (181,156)-(331,356) came back at exactly that rect in the 1024² plane's top-left quadrant (at the 1024 input content fills the plane, which is why input==output never exposed this). extractBestMask now (a) derives the plane side from the BLOB (trailing square plane with side = power of two in [64,4096], leading product = K; last axis == side → W=side,H=product/side; last axis == product → flattened side² → side×side; else unrecognized → empty mask) and (b) crops the chosen candidate to the top-left min(plane, MODEL_INPUT_SIZE) content region (submat+clone). (3) Retained dnn footprint does NOT shrink at 512: Debug.getNativeHeapAllocatedSize 2.8MB → 606.7MB after one detect → 15.2MB after release+gc → 607.4MB after re-detect (vs ~591MB @1024) — the memory argument for the input reduction is VOID (decoder-side fixed 1024² buffers dominate; the release+gc machinery stays the actual fix). (4) QUALITY NO-GO: a 300px square (29% of image width) segments fine (iou_predictions 0.844/0.852/0.840, clean 512² cropped mask, single-square erase passes) but a 200px square (19.5% width) came back only 30318/40000 = 75.8% covered by the hard mask (the other square 39883/40000; iou_predictions 0.77-0.82 are overconfident) → LaMa keeps the unmasked rim as context and reconstructs RED into the hole → eraseRegion_removesTwoDisjointSquares fails deterministically "left square area still red after the erase (pixel ffff060d)". Kept from the experiment: feather is MagicEraserEngine.samMaskFeatherKernel(actualMaskSide) = 3% → k=31 at the 1024² output**; out-parameter form `net.forward(List<Mat>, List<String>)` (the return-style named forward does NOT exist in the Java bindings; BOTH list args must be real java.util.ArrayList — the JNI hard-codes ArrayList.size(), CheckJNI aborts on Arrays.asList views). LaMa (512x512 input, blobFromImage 1/255 BGR no swap + mask binarized >0 AFTER the resize — resize first, threshold after, like the reference, via the reshaped 2-D view): CHW output → split/merge → saturating convertTo CV_8U (safer than the reference numpy wrap-cast). `MagicEraserEngine.convertStrokesToPrompts(strokes)` = union stroke bbox → 2 box entries + up to 4 evenly sampled fg points (proportional per stroke, dedup) capped at 6; `computeObjectMask(Bitmap, strokes)` = caller-owned `MagicEraserMask` via PER-OBJECT-GROUP prompting: SAM segments ONE object per prompt set, so the strokes are rasterized + connectedComponents-grouped (stroke joins the group of its first point; contiguous stroke paths guarantee one component per stroke), one prompt set + one `EfficientSamProcessor.computeRawMask(bitmap, points, labels, logPrefix)` run per group (largest first by point count, cap 8 — group diagnostics prefixed `group k/n:` in the SPIKE lines), raw (unfeathered, input-resolution after the fixed-1024²-plane crop) group masks unioned with `Core.max` and the union feathered (3% of the ACTUAL mask side via `samMaskFeatherKernel(maskSide)` → k=31 at the 1024² output plane, odd) + upsampled ONCE in the engine; single group degenerates to one SAM run; `hasMask` gate = mask sum ≥ 0.2% area (same as PersonSeg); `rasterizeMask` (package-private, tests only) = thick AA line segments + circle caps, thickness 1% of min dim per brush size step; `eraseRegion(Bitmap, mask)` = NEW mutable bitmap, never mutates the input: hard-binary threshold 127 (never feed feathered masks to LaMa) → mask bbox via findNonZero+boundingRect, +50% padding, >60% of image area → connectedComponents per-component crops (largest first, cap 8, single huge component → whole-image downscale fallback) → per-region LaMa crop inpaint, paste-back ONLY masked pixels with a 3%-of-region feathered mask (feather lives only at paste-back), every intermediate Mat released in finally; `toOverlayBitmap` = white-alpha ARGB bitmap for the :app overlay; `applyBatches(Bitmap base, List<StrokeBatch>, CancelledCheck)` = engine-owned batch replay (per-iteration cancelled check at loop top, intermediates+base recycled on success/failure, catch Exception|OOM → RuntimeException wrap — RxJava rethrows fatals), used by eraseObject + the page's restore/save/share; `eraseObject(Bitmap preview, List<StrokeBatch> history, ArrayList<EditorStroke> strokes, MagicEraserMask reusableMask, CancelledCheck)` → nested `EraseObjectResult` (result Bitmap + maskFound) = the whole erase pipeline core (replay → mask compute-or-reuse → eraseRegion) — CALLER TRANSFERS mask ownership (released in the engine's finally; the page also recycles the handed-over mask only on its pre-call decode-failure path — Bitmap.recycle is idempotent so the engine-finally double-recycle on an applyBatches failure is a benign no-op); cancelled checks sit BEFORE computeObjectMask and BEFORE eraseRegion (load-bearing: a dead consumer must not re-parse released nets); the 32-bit SAM-before-erase/LaMa-after RELEASE POLICY still lives in the :app page, not here (flagged: a second engine consumer must respect it or risk the SIGABRT); no-concurrent-calls contract on both processors (same rule as ST/PersonSeg). **Net lifecycle (the ~1GB OOM fix):** `release()` on EfficientSamProcessor/LamaProcessor is synchronized+idempotent (nulls the net, `IllegalStateException` guard on later inference, inference methods share the monitor so release can't race a forward). LOAD-BEARING binding fact: OpenCV 5.0.0.1 `Net.finalizeNet()` does NOT free (it prepares the execution session); the ONLY native free is `Net.finalize()` → private `delete(long)` — so release = reference-drop + explicit `System.gc()`+`runFinalization()` nudge (`nudgeNativeReclaim` in MLEngineInstance; a native malloc failure never triggers GC, and the finalizer deletion can lag — tests on low-RAM devices needed explicit gc/runFinalization preludes). cv::dnn RETAINS its activation/workspace buffers inside the net after forward (SAM@1024 ≈ 591-604MB retained, LaMa@512 ≈ hundreds of MB) — NEVER keep both nets resident, STRICTLY SEQUENTIAL: the :app page releases SAM before every erase, LaMa after every erase, both on editor dispose. Co-residency evidence (32-bit api24 x86 AVD): (a) long session → VA ceiling → LaMa 1.6MB forward OOM → pthread_create OOM during error scheduling → fatal RxJava crash; (b) FRESH process, resident SAM + LaMa load → instant NATIVE SIGABRT in libc++_shared.so (uncaught std::bad_alloc from dnn's raw operator new — NOT a CvException, uncatchable from Java, process death, no self-heal possible). With the sequential design: detect 591MB → erase with SAM freed succeeds → settled 9MB; the post-erase detect lazily reloads SAM and a reload OOM in long fragmented sessions is a CAUGHT CvException → user toast + self-heal. All `SPIKE:` diagnostics are gated behind `private static final boolean SPIKE_LOG = false` in all three classes (not ILogger — AndroidLogger(FILE, DEBUG) still writes debug to file in release)
- **Net lifecycle round 2 (deterministic teardown + face/ST hygiene):** `MLEngineInstance` implements `ProviderDisposable` — `dispose(Context)` is idempotent (mDisposed flag), per-entry try/catch releases every cached processor in all five maps (ST, PersonSeg, EfficientSam, LaMa, AiImageDetect), clears them, nulls the cached face models, one `nudgeNativeReclaim()` at the end. The cascade fires twice: SYNCHRONOUSLY via the `MLEngineProviderModule.dispose(Provider)` override (module dispose runs on the calling thread while the registry is still intact — the primary mechanism, so the next instrumentation class never races a pending release) and again ASYNC via the registry's ProviderDisposable entry on DefaultProvider's static shared executor (never shut down — BaseProviderModule shuts down a DIFFERENT app-registered pool; the second call is an idempotent no-op). FaceDetectorYN/FaceRecognizerSF are now lazily cached SHARED fields (getFaceDetectModel/getFaceRecognizerModel keep their signatures; ~37MB SFace parsed once per provider instead of per call); FaceEngine methods are all `synchronized` because each detect mutates the shared detector via setInputSize and the WeightedThreadPool(maxWeight 5) can overlap two face tasks; `releaseFaceModels()` (null + nudge) is submitted by FaceEditorPage.dispose mirroring MagicEraserEditorPage's SAM/LaMa release — next face session pays a seconds-long re-parse. `PersonSegEngine` also implements ProviderDisposable → releaseAllMasks (belt-and-braces over PortraitEditorPage). STProcessor/PersonSegProcessor gained the standard release()/checkNotReleased() contract (invoked ONLY by dispose — the caches keep app-lifetime semantics, no per-instance eviction API) plus full Mat hygiene (STProcessor leaked 4 Mats/call: input RGBA orphaned by reassignment, preprocess RGB, blob, forward output). LOAD-BEARING FaceRecognizerSF fact: feature() writes through an OutputArray that SHARES the net's internal output buffer by refcount — the second feature() call OVERWRITES the first result in place, so isFaceSimilar MUST clone each feature out before the next forward (an earlier plan to drop the clones as "defensive" would have made match() compare face2 with itself; caught by source-tracing face_recognize.cpp/net_impl.cpp/matrix_wrap.cpp). detectFaceRaw returns a caller-owned Mat (documented; callers release).

## Workers (`workmanager`)
- `ModelDownloadWorker` — the ONLY WorkManager worker left: unique work per model (`ExistingWorkPolicy.KEEP`), network-connected constraint, exponential backoff; input `Params.MODEL_TYPE` (model id string) + failure output `Params.ERROR_MESSAGE`; get deps via `BaseApplication.of(ctx).getProvider()`
- `ModelChangeNotifier` (`provider/notifier/`): hot progress/succeeded/failed flows — consumers must be subscribed at emit time

## Registration
`MLEngineProviderModule`: MLEngineInstance async (`registerAsync` starts construction on a background thread at provider START — not deferred to first get; get() blocks on the future); FaceEngine/QREngine/STEngine/PersonSegEngine/MagicEraserEngine/AiDetectEngine/ModelDownloader/ModelChangeNotifier lazy (`registerLazy` = supplier runs on first get(), synchronized, memoized).

## Adding an ML feature (canonical recipe)
1. model file: add a `ModelType` entry (id/displayName/displaySize/downloadUrl → downloaded via ModelDownloadWorker) OR bundle + register path constants in MLEngineInstance
2. engine method in FaceEngine/STEngine or a new engine; gate on `ModelCatalog.isAvailable` and push `ModelDownloadDialog` (`:app`) for on-demand download
3. register in MLEngineProviderModule; androidTest uses `MLEngineTestProviderModule` (+ `ModelTestHelper.installModels(provider, ModelType...)` — varargs so a test only downloads the models it needs; the no-arg overload installs the whole catalog — blocking download, needs network)

Tests (androidTest only, need emulator + network): ONE test class per engine component — `FaceEngineTest`, `STEngineTest`, `PersonSegEngineTest`, `QREngineTest` (15 tests, includes the qrCensor_* ZXing-oracle effectiveness tests, installs no models), `MagicEraserTest` (12 tests merged from the former EngineTest/OverlayTest/ProcessorReleaseTest/SpikeTest; NAME_ASCENDING is load-bearing: the SAM spike diagnostic runs FIRST on a clean no-net baseline, the LaMa-only spike runs after the erase tests' finally releases, the release-contract tests run LAST leaving empty caches for @AfterClass), `AiImageDetectProcessorTest` (release-contract test of the AI-image-detector processor; installs the AI model) (work-testing dep). Magic-eraser tests on the 32-bit api24 AVD must run in a FRESH process per class (force-stop first) — sequential tests fragment the 32-bit VA until even 192MB contiguous DNN allocations fail; the release tests double as the 32-bit survival pattern (release SAM before LaMa, gc/runFinalization preludes).
